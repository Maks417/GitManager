# Git Manager 1.2.0

This release adds remote configuration, reference comparison and recovery tools, and improves how the app restores your workspace.

## New features

- **Remotes & publishing:** add, edit and remove remotes, configure separate fetch/push URLs, change branch upstreams, and publish the current branch to an explicit remote and destination branch. Fetch and publication show progress and support cancellation.
- **Reference comparison:** compare branches, tags or commits as exact snapshots, or review a feature branch's changes since its common ancestor with the base. Inspect changed files, renames, line counts and image previews. Commit actions include **Compare with HEAD**.
- **Recovery:** browse saved backups and HEAD history, inspect commits that branches no longer reach, and create a branch to recover a commit. The app saves commits before amend, reset, rebase and branch deletion, and saves tracked edits before hard reset or discard. Restore tracked changes or explicitly remove a saved backup from the Recovery dialog.
- **Commit drafts:** each repository keeps its commit message across view changes, repository switches and app restarts. A successful commit clears its draft; a failed commit keeps it.

## Fixes

- Show named tag badges in History, including lightweight and annotated tags, instead of hiding their names behind the reference count. Long names and multiple tags fit within the commit row, with full names available on hover.
- Restore the previous maximized or full-screen window mode when reopening the app. **F11** and the View menu toggle full screen.
- Show a loading screen while saved repositories are restored. The repository welcome screen appears only after startup confirms there are no repositories, so it no longer flashes over an existing workspace.
- Offer retry when startup fails, and Git installation guidance when saved repositories cannot load because Git is unavailable.

## Notes

- Publication connects to an existing server repository and uses your Git credential helper or SSH agent.
- Recovery backups are local. Tracked-file snapshots exclude untracked files and submodule contents; untracked files discarded in the app go to the OS Trash. Restore requires a clean working tree and index with no Git operation in progress. A snapshot taken during conflicts keeps file content, but does not recreate the original unresolved index or operation.
- Feature and architecture documentation has been updated for these changes.
