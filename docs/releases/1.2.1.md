# Git Manager 1.2.1

This release separates remote configuration, branch tracking and publishing into focused flows.

## Improvements

- **Manage remotes:** open remote configuration from the Repository menu or the Remote branches menu. Add and edit forms appear on demand, with a separate push URL under Advanced. Saving a remote does not automatically fetch.
- **Branch tracking:** set or clear an upstream from a branch's action menu or the current branch's tracking status. Tracking status stays visible even when ahead and behind counts are zero, and available upstream choices can be refreshed in the dialog.
- **Publish branch:** every first push reviews the remote, destination branch and effective push URL before sending commits. Publication establishes tracking. If no remote is configured, add one within the same flow and then review the destination.
- **Push to:** send an already tracked branch to another destination. Existing tracking is preserved unless **Use this destination as upstream** is selected.
- **Branch actions:** checkout, merge, rebase, tracking and deletion are available from a visible overflow button, right-click and keyboard menus. Both history shortcuts remain visible.
- Dialogs support long branch names and URLs, narrow windows and both themes. Control labels have no trailing ellipses.

## Fixes

- Branch action hints remain visible at the window's left edge. Double-clicking empty space in a local or remote branch row checks out the branch, while action buttons retain their own behavior.
- Explicit pushes report success against the chosen destination, even when the existing upstream still lacks those commits.
- Publication checks that the reviewed source branch is still checked out. Branch dialogs close when their repository or branch target changes or disappears.
- Failed publication preserves entered values. Progress and cancellation are available in the dialog and toolbar, and focus returns to the initiating control after closing.

Remote URLs continue to point to existing server repositories. Authentication uses your Git credential helper or SSH agent.
